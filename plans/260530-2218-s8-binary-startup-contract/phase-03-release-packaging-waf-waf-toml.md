# Phase 3: Release packaging (./waf + ./waf.toml)

## Overview

A new release script `scripts/release-waf-bundle.sh` builds `target/release/waf` (now possible after Phase 1) and emits `./waf` + `./waf.toml` at the repo root in a single command. `./waf.toml` is **generated**, not committed (per design decision: "generated at release time"). Generation is deterministic: clone `configs/default.toml` and apply a small benchmark overrides table inline.

## Context Links

- Contract §8: `analysis/docs/EN_waf_interop_contract_v2.3.md` lines 504–528
- Phase 1 output: `target/release/waf` exists
- Phase 2 output: `./waf` finds `./waf.toml` automatically when launched from repo root
- Source config: `configs/default.toml`
- Adjacent precedent: `.github/workflows/release.yaml:108-112` already stages a `waf` binary for the release tarball — this script mirrors that locally

## Requirements

**Functional:**
- A single command produces `./waf` (executable) and `./waf.toml` (valid config) at repo root.
- `./waf.toml` is regenerated on every run (no stale-file detection — overwrite is the spec).
- `./waf.toml` is listed in `.gitignore` (or matches an existing pattern) — it is NOT committed.
- The script is idempotent: running twice yields byte-identical outputs.
- The script exits non-zero if either output is missing afterward.

**Non-functional:**
- POSIX `sh` only (no bashisms) so it runs on any benchmark image.
- No external dependencies beyond `cargo`, `cp`, `chmod`, `mktemp`, and standard `sed`/`awk`. No Python, no Node.
- Total script length under 80 lines.

## Architecture

### Inputs and outputs

```
inputs:
  configs/default.toml            ← canonical config (committed)
  scripts/release-waf-bundle.sh   ← this phase's deliverable
outputs:
  target/release/waf              ← cargo build artifact
  ./waf                           ← copy of target/release/waf, chmod 0755
  ./waf.toml                      ← rendered from configs/default.toml + interop overrides
```

### Overrides applied to `./waf.toml`

The benchmark runs against a single-host loopback configuration with no Docker. The generated config differs from `configs/default.toml` only where the contract demands or where the local-only runtime needs it. Concrete overrides (decide in this phase; keep minimal):

| Section.key | Default value | Benchmark value | Reason |
|---|---|---|---|
| `[proxy] listen_addr` | `0.0.0.0:80` | (keep as-is unless benchmark uses non-privileged port) | The benchmark spec dictates this; **confirm with the contract harness before locking** |
| `[proxy] listen_addr_tls` | `0.0.0.0:443` | (keep) | Same as above |
| `[proxy] tls_cert_pem`, `tls_key_pem` | `/etc/prx-waf/tls/…` | local path under `data/tls/…` or self-signed generated by existing `ensure_self_signed_cert` | The benchmark won't have `/etc/prx-waf/` |
| `[storage] database_url` | `postgresql://prx_waf:prx_waf@postgres:5432/prx_waf` | (TBD — does the benchmark need persistence?) | Benchmark may require a sqlite/in-memory shim. **Open question.** |
| `[panel] config_path` | `waf-panel.toml` | (keep) | OK as relative |
| `[victoria_logs] enabled` | `true` | `false` | VictoriaLogs sidecar adds startup time and external state. Disable for benchmark. |
| `[interop] audit_log_path` | (not yet present) | `./waf_audit.log` | Added by parent plan §6 work; reference it here for completeness |
| `[interop] benchmark_secret` | (not yet present) | `waf-hackathon-2026-ctrl` | Added by parent plan §2 work; reference it here for completeness |

**Important:** The `[interop]` section keys (`audit_log_path`, `benchmark_secret`) are produced by parent-plan Phases 3 and 4 in `260527-1157-waf-interop-v23-critical-compliance`. This phase **only writes the keys into `./waf.toml`** when they are valid in the schema. If parent plan §2/§6 ship after this phase, the script's `[interop]` block is harmless dead config (loader will warn-and-ignore unknown keys, matching existing behavior).

**Open question:** confirm the benchmark spec's actual listen addresses, port expectations, and database expectations from the harness team before locking the overrides table. Flagged below.

### Generation strategy

Two acceptable approaches; pick **A** unless reviewer prefers **B**:

- **(A) Append-overrides:** `cp configs/default.toml waf.toml`, then append an `# ── Interop overrides ─────` block at the end. TOML parser respects last-write-wins for duplicate keys in the same `[section]`, so the appended `[victoria_logs] enabled = false` overrides the original. Simplest, no parser needed. **Verify last-write-wins behavior in our TOML parser (`toml` crate)** before relying on it; if not last-write-wins, fall back to (B).
- **(B) Awk/sed pipeline:** transform `configs/default.toml` line-by-line, substituting overridden keys in place. More fragile (TOML is whitespace-sensitive) but no duplicate-key risk.

Decision: **try (A); fall back to (B) if `toml` crate rejects duplicates.**

## Implementation Steps

1. **Confirm TOML last-write-wins** (5 min): write a 4-line probe that parses a string with duplicate keys via the `toml` crate (already a workspace dep) and inspect which value survives. If last-write-wins, proceed with approach (A); else (B).

2. **Draft `scripts/release-waf-bundle.sh`:**

   ```sh
   #!/bin/sh
   # Build the benchmark/release bundle for §8 of the WAF interop contract.
   # Produces:
   #   ./waf       — release binary (copy of target/release/waf)
   #   ./waf.toml  — rendered config, derived from configs/default.toml
   # Idempotent: safe to re-run; overwrites previous outputs.
   set -eu

   ROOT="$(CDPATH= cd -- "$(dirname -- "$0")/.." && pwd)"
   cd "$ROOT"

   SRC_CONFIG="configs/default.toml"
   [ -f "$SRC_CONFIG" ] || { echo "ERROR: $SRC_CONFIG missing" >&2; exit 1; }

   echo "Building release binary..."
   cargo build --release --locked -p prx-waf

   BIN_SRC="target/release/waf"
   [ -x "$BIN_SRC" ] || { echo "ERROR: $BIN_SRC missing — confirm Phase 1 rename" >&2; exit 1; }

   echo "Staging ./waf..."
   install -m 0755 "$BIN_SRC" "$ROOT/waf"

   echo "Rendering ./waf.toml..."
   cp "$SRC_CONFIG" "$ROOT/waf.toml"
   cat >> "$ROOT/waf.toml" <<'EOF'

   # ── §8 interop overrides (generated by scripts/release-waf-bundle.sh) ─────
   # Edits here are LOST on next release. Edit configs/default.toml or this
   # script's heredoc instead.

   [victoria_logs]
   enabled = false

   [interop]
   audit_log_path = "./waf_audit.log"
   benchmark_secret = "waf-hackathon-2026-ctrl"
   EOF

   [ -x "$ROOT/waf" ]      || { echo "ERROR: ./waf not produced" >&2; exit 1; }
   [ -f "$ROOT/waf.toml" ] || { echo "ERROR: ./waf.toml not produced" >&2; exit 1; }
   echo "OK: ./waf and ./waf.toml ready."
   ```

3. **Make executable and run** from a clean checkout:
   ```sh
   chmod +x scripts/release-waf-bundle.sh
   scripts/release-waf-bundle.sh
   file ./waf            # → ELF 64-bit (or Mach-O on dev macs)
   head -5 ./waf.toml    # → starts with the [proxy] block from default.toml
   tail -10 ./waf.toml   # → shows the interop overrides
   ```

4. **Validate `./waf.toml` parses** under the existing loader:
   ```sh
   ./waf -c ./waf.toml run &
   PID=$!
   sleep 2
   kill $PID
   ```
   If `load_config` rejects the duplicate `[victoria_logs]` block, fall back to overrides-strategy (B) — replace the heredoc with a sed/awk pipeline that mutates lines in place. Document the chosen path inline in the script.

5. **Add `.gitignore` entries:**
   ```
   /waf
   /waf.toml
   ```
   Leading `/` anchors to repo root so paths like `crates/foo/waf` (none exist today but defensive) aren't accidentally ignored.

6. **Write E2E harness** `tests/e2e/s8-release-bundle-test.sh` that:
   - Removes `./waf` and `./waf.toml` if present.
   - Runs `scripts/release-waf-bundle.sh`.
   - Asserts both outputs exist with the expected permissions.
   - Re-runs and asserts outputs are byte-identical (idempotency).
   - Exits 0 on success, 1 with diagnostic on failure.

7. **Pre-push formatting** per `CLAUDE.md`: `cargo fmt --all` (no Rust edits this phase, but verify clean) and shellcheck the new scripts:
   ```sh
   shellcheck scripts/release-waf-bundle.sh tests/e2e/s8-release-bundle-test.sh
   ```

## Risk Assessment

| Risk | Likelihood | Mitigation |
|---|---|---|
| TOML parser rejects duplicate sections → ./waf.toml invalid | Medium | Step 1 probe; fall back to in-place edit (approach B) |
| Overrides drift from `configs/default.toml` as new fields are added there | Medium (over time) | Overrides are purely additive; new fields in default.toml propagate automatically via `cp` |
| `cargo build --locked` fails if `Cargo.lock` was updated but not committed | Low | The release flow is run from clean checkouts; `--locked` is intentional |
| Generated `./waf.toml` is accidentally committed | Low | `.gitignore` entries; pre-commit hook (out of scope here) |
| `install -m 0755` not available on all POSIX shells | Negligible | Standard on coreutils; benchmark runner ships coreutils |
